WHAT EACH NORMAL FORM MEANS:
─────────────────────────────────────────────────────────────────────────

1NF (First Normal Form)
  - Atomic values only
  - No repeating groups
  - Each column has unique values

2NF (Second Normal Form)
  - Meets 1NF requirements
  - No partial dependencies
  - All non-key attributes depend on ENTIRE primary key

3NF (Third Normal Form)
  - Meets 2NF requirements
  - No transitive dependencies
  - Non-key attributes depend only on primary key

BCNF (Boyce-Codd Normal Form)
  - Stricter than 3NF
  - Every determinant is a candidate key
  - Rarely needed in practice

═════════════════════════════════════════════════════════════════════════════

COMMON VIOLATIONS TO SPOT:
─────────────────────────────────────────────────────────────────────────

PARTIAL DEPENDENCY (2NF Violation):
  Problem: Non-key column depends on part of composite key
  Example: In (StudentID, CourseID) → StudentName depends only on StudentID
  Solution: Move StudentName to separate table with StudentID

TRANSITIVE DEPENDENCY (3NF Violation):
  Problem: Non-key column depends on another non-key column
  Example: PatientID → DoctorID → DepartmentID
  Solution: Create separate table for intermediate dependency

MULTIPLE CANDIDATE KEYS:
  Problem: Table has more than one possible primary key
  Example: StudentID or StudentEmail could both be primary key
  Solution: Choose one as primary, others as unique constraints
